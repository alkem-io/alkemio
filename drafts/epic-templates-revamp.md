## Description
Reusing a template across Spaces is hard today. You can't save a template straight to where you want it, you can't apply a library template where you are, you can't share a link to one, previews are incomplete, and some content gets lost when a template is saved or applied.

This parent epic covers the full revamp of templates, from creating them to using, sharing and curating them. It replaces the earlier template library epics.

## Goal
Anyone can save content as a template to any library they're allowed to use, and apply any template they can see directly where they are.

## Hypothesis
Better template UX means more reuse by facilitators, better-structured new Spaces, and more value from the platform. We measure this through the share of new (Sub)spaces created from a template and how many templates are saved and applied each month.

## Sub-epics
1. **Foundations**: templates save and apply without losing data; reliable API; faster template explorer
2. **Create**: save a callout, whiteboard or (sub)space as a template, and choose where it goes
3. **Find & preview**: full previews, clear Space vs Subspace templates, shareable links
4. **Use**: apply a template directly from any library; import a full template pack
5. **Libraries & packs**: how the Space library, template packs and the platform library fit together; default templates managed in the admin UI
6. **Governance**: store-listing approval and roles on template packs

## Must have scope
- [ ] Templates save and apply without data loss
- [ ] Save as template, with a choice of destination
- [ ] Apply a Space / Subspace template directly from any library
- [ ] Import a full template pack into a Space library
- [ ] Full preview of Space templates
- [ ] Shareable template link

## Open questions
- [ ] Do packs live inside the Space library, or are their templates copied in?
- [ ] Should the Space library be visible to all members?
- [ ] How far down the hierarchy does "apply directly" go?
- [ ] Is an applied template a one-off copy, or does it stay linked to its source?
